AWS Developer Prep: DB & Caching

AWS Databases & Caching Notes

Detailed summary based on Stephane Maarek's AWS Certified Developer material covering RDS, Aurora, RDS Proxy, ElastiCache, and MemoryDB.

1. Amazon RDS Fundamentals

  • Managed Engines: Postgres, MySQL, MariaDB, Oracle, MS SQL Server, DB2, Aurora.
  • Managed Benefits: Provisioning, patching, PITR automated backups, monitoring, scaling.
  • SSH Limit: You cannot SSH into standard RDS instances.
  • Storage Auto Scaling: Scales dynamically when free storage < 10% for 5+ mins, 6 hours elapsed since last change, and Max Threshold is set.

2. Read Replicas vs. Multi-AZ

  • Read Replicas: Up to 15; Asynchronous replication; used for read scaling (SELECTs); can be Cross-AZ or Cross-Region (Cross-Region incurs network fees).
  • Multi-AZ (DR): Synchronous replication; single DNS endpoint; automatic failover for high availability; not used for scaling.
  • Single to Multi-AZ: Zero-downtime operation (takes snapshot, restores to new AZ, synchronizes).

3. Amazon Aurora

  • Performance: Proprietary AWS DB; 5x MySQL performance, 3x Postgres performance.
  • Resilience: 6 copies across 3 AZs (requires 4/6 for writes, 3/6 for reads). Storage auto-expands from 10 GB up to 128 TB / 256 TB.
  • Endpoints: Writer Endpoint (points to master) and Reader Endpoint (connection load balancing across replicas).
  • Features: Sub-10ms replica lag, zero-downtime patching, and Backtrack (PITR without backups).

4. RDS Proxy & Security

  • RDS Proxy: Serverless pool manager; reduces CPU/RAM load; cuts failover time by up to 66%; must be accessed inside a VPC (never public).
  • At-Rest Encryption: AWS KMS required at creation. Unencrypted DBs must be encrypted via snapshot and restore.
  • Auth & Audit: Supports IAM DB authentication (credentials in Secrets Manager) and CloudWatch Audit Logs.

5. ElastiCache: Redis vs. Memcached

  • Purpose: In-memory database with sub-millisecond latency for read-heavy workloads or session management.
  • Redis: Multi-AZ with Auto-Failover, Read Replicas, Data Durability (AOF), backups, and complex types (Sets/Sorted Sets).
  • Memcached: Pure in-memory (no persistence), multi-threaded, multi-node data partitioning (sharding), no native HA.

6. Caching Strategies & MemoryDB

  • Lazy Loading (Cache-Aside): Reads cache first; miss triggers DB query and cache update. Avoids clutter, but incurs a 3-round-trip penalty on misses.
  • Write-Through: DB and cache are updated simultaneously on write. Ensures fresh data, but adds write latency and potential cache churn.
  • TTL & Eviction: Items are removed explicitly, via LRU on full memory, or via Time-To-Live expiration.
  • MemoryDB for Redis: Durable in-memory database using a Multi-AZ transactional log for microservices.
