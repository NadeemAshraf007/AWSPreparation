Topic: Elastic Beanstalk & CloudFormation

1. Elastic Beanstalk Overview

  • Concept: Developer-centric view of deploying applications on AWS. It handles provisioning, load balancing, auto-scaling, and health monitoring automatically.
  • Cost: Elastic Beanstalk is free; you pay only for the underlying AWS resources (EC2, ELB, RDS, etc.)[cite: 1].
  • Supported Platforms: Go, Java SE, Java with Tomcat, .NET Core/Windows, Node.js, PHP, Python, Ruby, Packer, Single/Multi-container Docker, and Preconfigured Docker[cite: 1].
  • Environment Tiers:
    • Web Server Tier: Standard web app tier behind an ELB connected to an Auto Scaling Group[cite: 1].
    • Worker Tier: Pulls tasks off an Amazon SQS queue and processes them asynchronously[cite: 1]. Scales based on SQS queue size[cite: 1].

3. Essential Configuration & Management

  • EB Extensions: Configured using .config files in the .ebextensions/ directory at the root of the source code[cite: 1]. Written in YAML or JSON format[cite: 1]. Can provision custom resources like RDS, ElastiCache, or DynamoDB[cite: 1].
  • Lifecycle Policy: Elastic Beanstalk can store at most 1,000 application versions[cite: 1]. Lifecycle policies automatically remove old versions based on time or total space[cite: 1]. Currently deployed versions will not be deleted[cite: 1].
  • Database Best Practices:
    • Dev/Test: Database can be created inside Elastic Beanstalk[cite: 1].
    • Production: Database should be created externally (standalone RDS) and connected via environment variables[cite: 1]. This decouples the database lifecycle from the Elastic Beanstalk environment lifecycle[cite: 1].
  • CLI Commands: Key commands include eb create, eb status, eb health, eb events, eb logs, eb open, eb deploy, eb config, and eb terminate[cite: 1].
  • Under the Hood: Elastic Beanstalk uses AWS CloudFormation to provision resources[cite: 1].
