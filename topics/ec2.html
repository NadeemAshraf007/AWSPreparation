EC2, EBS, EFS, Elastic Load Balancing, and Auto Scaling Study Guide

1. Amazon EC2 Fundamentals

  • Infrastructure as a Service (IaaS): Rent virtual machines, persistent block storage (EBS), distributed traffic (ELB), and auto-scaling (ASG).
  • EC2 User Data: Bootstrapping scripts that run only once on the first launch of the instance with root privileges.
  • Instance Naming Convention: e.g., m5.2xlarge → m (class), 5 (generation), 2xlarge (size).
Instance Families:
  • General Purpose: Balanced compute, memory, networking (e.g., t2.micro, m5).
  • Compute Optimized: Batch processing, HPC, media encoding (e.g., c5).
  • Memory Optimized: In-memory caches (Redis), real-time big data, databases (e.g., r5, x1).
  • Storage Optimized: High sequential read/write, OLTP systems, NoSQL (e.g., i3).

3. Security Groups & Classic Ports

  • Security Groups act as a stateful firewall for EC2 instances at the ENI level.
  • Contain ALLOW rules only (no deny rules).
  • All inbound traffic is blocked by default; all outbound traffic is allowed by default.
  • Timeouts indicate Security Group blockages; "Connection Refused" indicates application error.

4. Storage Options: EBS vs Instance Store vs EFS

  • EBS (Elastic Block Store): Network drives bound to a single Availability Zone. Must snapshot to move across AZs.
    • gp2/gp3: General Purpose SSD (Boot volumes supported).
    • io1/io2 Block Express: Provisioned IOPS SSD for high-performance DBs (Supports EBS Multi-Attach).
    • st1 / sc1: HDD options (cannot be used as boot volumes).
    • Delete on Termination: Root volume deleted by default; attached volumes kept by default.
  • EC2 Instance Store: Local physical hardware drive. Extremely high IOPS, but ephemeral (data is lost if instance stops).
  • Amazon EFS: Managed NFS shared file system across multiple AZs for Linux instances (POSIX compliant).

5. Elastic Load Balancing (ELB) & Auto Scaling (ASG)

  • Application Load Balancer (ALB): Layer 7 (HTTP/HTTPS/WebSocket). Path-based routing, Host-based routing, query string routing. Client IP retrieved via X-Forwarded-For header.
  • Network Load Balancer (NLB): Layer 4 (TCP/UDP). Ultra-low latency, millions of requests/sec, provides static/elastic IPs per AZ.
  • Gateway Load Balancer (GWLB): Layer 3 (IP network packets). Operates on port 6081 using GENEVE protocol for 3rd-party security appliances.
  • Stickiness: Binds user session to a specific target via cookies (e.g., AWSALB).
  • SNI (Server Name Indication): Allows loading multiple SSL/TLS certificates on a single ALB/NLB listener.
  • Auto Scaling Cooldown: Default 300 seconds to allow metrics to stabilize before triggering another scale action.
